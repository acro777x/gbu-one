EAS project id for push registration: [OPEN — owner action required] The app needs an EAS project id before Expo can issue a push token (`extra.eas.projectId` in `app.json`, or `eas init` to create the project). No id is committed to the repo because inventing one would only produce a token the Expo servers reject. Until it is supplied, `registerDeviceForPush()` returns the skip reason `missing-eas-project-id` and the app runs normally without push. Owner: run `npx eas init` (or paste the id from the Expo dashboard) and add it to `app.json` under `expo.extra.eas.projectId`. No code change is needed — `src/lib/pushNotifications.ts` reads it at runtime.

FCM / APNs credentials for the release build: [OPEN — owner action required] A signed Android build that receives pushes needs the FCM `google-services.json` (`android.googleServicesFile`) and the matching APNs key/certificate for iOS. These are owner-owned credentials and are never committed. The worker already sends through the Expo Push API using `EXPO_ACCESS_TOKEN` (`worker/pushSender.ts`), so the app side only needs the device token, which the EAS project id unlocks (see #11).
13. 16 KB page-size support for a Play Store release: [OPEN — needs an SDK upgrade] Android 15+ runs apps whose native libraries are not built for 16 KB pages in a compatibility mode, and Google Play requires 16 KB support for new uploads. This repo already does its part: `plugins/withReleaseSigning.js` pins the NDK to r27 and adds `-DANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON`, which makes every library compiled here 16 KB aligned (measured on the release APK: 6 of 24 native libraries, including `libappmodules.so` and `libc++_shared.so`). The remaining 18 are **prebuilt** binaries inside the React Native 0.76 / Expo SDK 52 AARs (`libreactnative.so`, `libhermes.so`, `libfbjni.so`, `libjsi.so`, `libreanimated.so`, `libworklets.so`, …) and cannot be fixed by the project. Closing this needs **Expo SDK 53 / React Native 0.79+**, which ship 16 KB aligned prebuilts. Owner decision: upgrade the SDK (larger change, touches every native dependency) or publish with the compatibility mode. The app runs correctly either way. Details and the release steps are in `docs/RELEASE.md`.
